# lark-agent-x-ts

A TypeScript port of [LarkAgentX](https://github.com/cv-cat/LarkAgentX): a personal-account messaging channel over the internal protocol of the Feishu / Lark web client (QR-code login, receiving messages over a persistent connection, sending messages as yourself, marking read, message links, arbitrary gateway endpoints). The CLI is packaged by Bun as a single file; the library entry point can be embedded in a Node process.

## Common commands

```bash
bun install
bun test                       # unit tests + parity tests against the original
bun run test:node              # compile the library to lib/ and run smoke tests under Node
bun run typecheck && bun run lint
bun run build                  # dist/lark (single file for the current platform)
bun src/cli/main.ts <command>  # run from source
```

After every change, run at least `bun test && bun run typecheck && bun run lint`; if you touched code reachable from the library entry point (see below), also run `bun run test:node`.

## Layout

- `src/client.ts`: gateway client (HTTP + protobuf) and the persistent message connection; `src/mail.ts`: Lark Mail (`client.mail`) over the same gateway, plus Drive attachment upload/download; `src/auth.ts`, `src/region.ts`: login and credentials; `src/http.ts`: requests and error types.
- `src/proto/`: protocol asset loading (`assets.ts`, `registry.ts`), message decoding (`decoders.ts`), request building (`builders.ts`), protobuf ↔ dict (`dict.ts`).
- `src/storage/` (`Bun.SQL`), `src/agent/` (`Bun.spawn`), `src/cli/`: CLI only.
- `src/index.ts`: library entry point; `src/log.ts`: logging (loguru line format; can be routed to a host via `setLogSink`).
- `assets/`: protocol assets (`*.binpb`, `cmd_map.json`), generated by `scripts/proto-pipeline/` from the messenger bundles plus the Lark Mail bundle (`scripts/proto-pipeline/mail.ts`); never edit by hand.
- `tests/`: `bun:test`; `tests/node/lib.smoke.mjs` is the Node smoke test; `tests/fixtures/parity.json` holds the parity fixtures.

## Hard constraints

- **Compatible with the fork**: commands, arguments, stdout, exit codes, the data directory, and the `credentials.json` and `messages.db` formats stay identical; see `docs/compat.md`. Any new intentional difference must be recorded in its table.
- **Encoding/decoding follows the original**: after changing `src/proto/`, `tests/parity.test.ts` must pass. The parity fixtures are generated by `scripts/gen-parity-fixtures.py` in a Python environment with the fork installed; never edit `parity.json` by hand.
- **The library entry point must run under Node**: modules reachable from `src/index.ts` must not use `Bun.*` or `bun:*`; protocol assets are always read via `readAsset()` (single-file builds register embedded paths in `src/bun-assets.ts`, which is also exported as `lark-agent-x-ts/bun-assets` for Bun embedders building single-file binaries). When exports or signatures change, update "Using as a library" in the README, and write `BREAKING CHANGE` in the commit for breaking changes. Embedders pin versions by commit via a git dependency.
- **Tests never touch a real account**: use `Bun.serve` to run a fake server, or replace `api` / `gatewayPost`; use synthetic ids like `7000000000000000001`, and placeholder person and group names like "同事甲" (Colleague A) and "项目协作群" (Project team), matching the existing test data.
- **When testing against a real account**: make read-only calls only; to verify sending, send only to your own chat (`lark self-chat`). Credentials live only in `~/.larkx`; never print or commit them.
- **Publishing boundary**: the original project has no open-source license. This repository publishes its source but ships no license and is not published to npm (as stated in "Origin and acknowledgements" at the end of the README). Do not add a LICENSE or change the publishing fields in `package.json` on your own.

## Code conventions

- TypeScript strict / ESM, Biome for formatting and lint; file names in kebab-case or matching the original project's module names.
- Code comments and docs are in English; comments state intent and constraints, not a restatement of the code. User-facing log, error and CLI output strings stay as they are (Simplified Chinese), because they must match the original Python fork's output; see `docs/compat.md`. New commands with no counterpart in the fork (e.g. `lark mail`) print English.
- Error types: `AuthExpired` (credentials expired, re-login required), `NetworkError` (network failure, not necessarily a credentials problem), `HttpError` (non-2xx), `SendUnconfirmed` (accepted by the server but no message id returned), `PermissionDenied` (blocked by permission rules; see `src/permissions.ts`). Callers handle these distinctly; don't collapse them into a plain `Error`.
- Log through the logger in `src/log.ts`, never `console.*` directly (except for CLI stdout).
- Commit messages are short English Conventional Commits.
